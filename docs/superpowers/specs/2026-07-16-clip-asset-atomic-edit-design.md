# 单片段出场资产原子编辑设计

## 问题

具体片段中的出场角色形象、场景文案和多项选择目前通过多个顺序请求保存。每个请求都重新读取 React 闭包中的旧 `clips` 数据，因此后一个请求会覆盖前一个请求，或误判旧值仍然存在。角色修改可能保留旧值并追加新值，场景修改可能删除旧值后跳过新增。

## 范围

- 修复具体片段视图中的出场角色、出场场景和道具选择保存。
- 允许在具体片段中修改已选角色形象文案和场景文案。
- “全部片段”视图保持现有选择和删除行为；角色、场景文案继续只读，本次不改变其保存语义。
- 不修改资产库中的角色形象名称、场景名称或图片。
- 不新增服务端接口或数据库字段。

## 数据流

编辑弹层继续维护 pending selection 和 pending label。用户确认时，组件把当前片段、资产库数据和全部 pending 状态交给纯计算函数：

1. 角色计算函数生成完整 `characters` JSON，保留未涉及的角色，并以最终 pending 形象集合替换本次编辑涉及的角色形象。
2. 场景计算函数生成完整 `location` 字符串，保留未涉及的场景，并以最终 pending 场景集合及文案替换旧值。
3. 道具计算函数生成完整 `props` JSON，保留最终 pending 道具集合。

每类确认操作对目标片段最多发送一次 PATCH。保存函数不再通过多次 `remove` / `add` 调用拼接最终结果。

## 组件边界

- `asset-state-utils.ts`：新增单片段最终状态计算函数，负责解析旧格式、匹配资产和序列化最终字段。
- `ScriptViewAssetsPanel.tsx`：收集 pending 状态并调用一个原子确认回调；成功后关闭弹层，失败时保持打开。
- `ScriptViewRuntime.tsx`：接收原子确认请求并对当前片段执行一次 `onClipUpdate`，同时更新本地选择状态。

## 错误处理

- 无目标片段、资产不存在或最终状态无法解析时，拒绝保存，不发送部分 PATCH。
- PATCH 失败时保留编辑弹层和 pending 状态，并显示安全错误信息，方便重试。
- 保存中禁用重复确认。

## 验证

遵循项目所有者先前要求，不新增或运行自动化测试。使用一次性静态复现脚本验证角色改名、场景改名和多选修改只产生一个最终值；再运行 TypeScript、改动文件 ESLint 和 `git diff --check`。
