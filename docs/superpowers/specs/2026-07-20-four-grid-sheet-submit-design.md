# 四宫格整图生成与裁剪修复设计

## 背景与根因

四宫格的目标流程是“一次生成一张完整 2×2 故事板整图，再从整图裁剪四个分镜”。现有后端整图任务本身符合这一目标：`storyboard_sheet_generate` 只调用一次生图 provider，也不存在把四张图片合成整图的代码。

当前“点击生成 2×2 四宫格没有反应”的根因在前端任务状态：四宫格按钮复用了 `storyboardTaskRunning`。该状态同时包含文本重生成、插入分镜和整图生成/裁剪任务；无关任务或残留运行态都会让按钮直接 `disabled`，点击事件不会触发，因此 API 与 ComfyUI 都收不到任务，页面也没有解释。

此外，四宫格的单格数据仍可通过通用单图接口被直接生图。虽然当前 UI 已尽量隐藏该入口，但后端没有强制保证“整图后裁剪”，仍可能被旧页面、缓存页面或直接 API 调用绕过。

## 目标行为

四宫格和六宫格统一遵循以下状态流：

1. 故事板规划生成四个有序的文字分镜，供整图提示词使用。
2. 用户点击“生成 2×2 四宫格”。
3. 页面立即进入“正在提交”状态，并向 `/storyboard-sheet` 发送一次请求。
4. 后端创建一个 `storyboard_sheet_generate` 任务，生图 provider/ComfyUI 只收到一次整图生成调用。
5. 成功后页面展示一张完整 2×2 整图。
6. 用户点击裁剪，系统从该整图按行优先裁成四张分镜图片。

系统不得把四张独立生成的图片拼成四宫格，也不得在整图生成前把四个单格当作独立生图目标。

## 前端状态设计

### 独立任务状态

把故事板任务状态拆成两类：

- 文本任务：`regenerate_storyboard_text`、`insert_panel`。
- 宫格整图任务：`storyboard_sheet_generate`、`storyboard_sheet_upscale`、`storyboard_sheet_crop`。

`GridGroupControls` 的生成按钮只由以下状态禁用：

- 当前按钮请求仍在本地提交中；
- 当前故事板确有进行中的宫格整图任务。

文本任务不得锁住整图生成按钮。服务端返回的整图任务状态仍用于防止重复提交。

### 可见反馈

- 请求发出后，按钮立即显示提交/排队状态。
- API 提交失败时，清除本地忙碌状态，并在控件内显示服务端错误。
- 如果按钮因真实宫格任务运行而禁用，显示明确的运行状态；不再出现“能看到按钮但点击完全没反应”。
- 整图未生成前，裁剪按钮保持禁用并说明需要先生成或上传整图。

## 后端流程约束

### 整图接口

`/storyboard-sheet` 保持现有单次 provider 调用：使用完整宫格提示词、整图比例和资产参考图创建一个 `storyboard_sheet_generate` 任务。此次修复不增加任何图像拼接步骤。

### 单格生图防绕过

通用面板单图生成接口读取目标 panel 所属 storyboard：

- `layoutMode='individual'`：保持现有单图生成行为。
- `layoutMode='four_grid'` 或 `layoutMode='six_grid'`：拒绝普通单图生成，返回 `INVALID_PARAMS`，子码 `GRID_PANEL_INDIVIDUAL_GENERATION_UNSUPPORTED`。

宫格面板允许的图像操作仍包括：

- 从整图裁剪；
- 对裁剪结果执行已配置的放大；
- 重新裁剪或撤回派生图；
- 上传外部完整宫格整图后裁剪。

## 数据与兼容性

- 不新增数据库字段或迁移。
- 已有完整整图、裁剪图和上传图继续有效。
- 不清空现有单格图片；只阻止新的宫格单格独立生成请求。
- 四宫格与六宫格共用同一套整图任务状态边界，避免两个模式再次漂移。

## 错误处理

- 前端保留服务端错误详情，不把提交失败吞成无响应。
- 工作流未发布、未测试、比例不支持或参数映射错误时，按钮下直接显示已有的规范错误信息。
- 本地提交失败必须清除 optimistic overlay；服务端已成功创建任务时则交由任务状态查询接管。

## 验证范围

补充或更新测试源码以覆盖：

- 文本任务运行时，四宫格整图按钮仍可提交。
- 宫格整图任务运行时，按钮禁用并显示状态。
- 点击四宫格按钮只提交一次 `/storyboard-sheet` 请求。
- 请求失败后错误可见且按钮恢复。
- 四宫格/六宫格面板调用普通单图生成接口会被后端拒绝。
- individual 模式仍可正常单图生成。
- 完整整图生成后才能进入裁剪，外部整图上传仍可直接裁剪。

遵照用户当前约束，本次只编写测试源码和执行静态检查，不运行测试、构建、TypeScript、Prisma 或 provider/ComfyUI 集成验证；运行时验证由用户完成。
